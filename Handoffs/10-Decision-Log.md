# Decision & Assumption Log

A living record of judgment calls made *during implementation* — different from `09-Assumptions-and-Provenance.md`, which covers assumptions already baked into the specification before any code existed. This log is written and appended to by whichever agent or developer is building the system, so the project owner can review every autonomous call after the fact without being interrupted for each one individually.

## Policy — when to log-and-proceed vs. stop-and-ask

This mirrors the policy stated in `CLAUDE.md`; repeated here for convenience since this is the file where it gets applied.

**Log it and keep going** when the decision is: an implementation detail the docs don't pin down (folder structure, package choice, ORM, testing framework, code style, exact microcopy or colors not specified in `06-Frontend-UI-Spec.md`); or filling a genuinely open gap where the docs already imply a clear, uncontroversial answer.

**Stop and ask instead of deciding** when the decision would: resolve or override a flagged assumption in `09-Assumptions-and-Provenance.md`; pull scope in from `11-Future-Expansion.md`; change a number, weight, or threshold stated as decided in `04-Prolog-Reasoning-Module.md` or `05-API-and-Backend-Logic.md`; change the stack (Next.js / SWI-Prolog / PostgreSQL); or is otherwise irreversible or expensive to undo.
